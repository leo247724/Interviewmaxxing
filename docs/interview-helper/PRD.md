# Interview Helper — first-version PRD

Status: MVP implemented and integrated acceptance passed, 2026-10-02; personal mock ready for user input. Owner: Leo. Coordinator: Codex.

## Outcome and scope

Add an **Interviews** tab to Interviewmaxxing. Leo prepares against a real job and practices aloud with a demanding simulated interviewer for the scheduled interview duration. The interviewer uses the job description, company/job notes, candidate resume/profile, optional LinkedIn text, and recordings/transcripts from previous rounds. Jev judges each completed answer through OpenRouter, with a final actionable scorecard and comparable practice history. The first real use is Leo's upcoming second-round NeuroScale interview for Founding Performance Marketing Lead: https://jobs.ashbyhq.com/neuroscale/b276f4e7-16f3-4979-acb0-506ac9366328 .

All original requirements remain in scope. Text mode helps accessibility and diagnosis but does not satisfy the voice acceptance gate. A fixture-only demo does not satisfy live-provider acceptance. The user's first personal mock follows MVP verification and requires their microphone participation; prior-round material is optional; synthetic tests must never appear as their actual performance.

## Experience

1. Open Interviews. See prior practices, readiness, and New interview.
2. Select/import a tracked job or enter URL, company, title, description. Review imported evidence. Add notes. Reuse existing candidate profile/resume evidence, permit resume text/document and optional LinkedIn profile text. Never invent missing candidate facts.
3. Choose round, interviewer role, minutes, and readiness target (default 80/100, an internal practice benchmark, not an offer probability). Defaults: round 1 recruiter; round 2 hiring manager; round 3 executive. Role remains editable: round does not prove who actually interviews Leo.
4. Upload a prior-round transcript or recording. Show transcription/indexing progress, source names, chunk count and recoverable errors. Recordings use ElevenLabs transcription and become retrievable chunks. A later-round mock can proceed with a visible missing-context note; uploaded context must actually be retrieved during interviewing/scoring.
5. Start the timed mock and explicitly enable microphone. Hear the agent, interrupt naturally, see connection/mic status, remaining time, transcript and per-answer scoring. Questions use the actual job and prior-round unresolved points. The agent asks one question at a time and presses evasions, vague claims, causal attribution, metrics, ownership, tradeoffs and inconsistencies.
6. Jev evaluates completed answers asynchronously without blocking conversation. Surface pending/failed judgments honestly. End manually or at server-enforced deadline; stop audio and show final scorecard with evidence, weak dimensions, specific next drills and unanswered issues.
7. Repeat against the same context. Retain previous sessions and show score change/trend on the same versioned rubric. Preparation is iterative rather than a one-off transcript.

## Interviewer and grading behavior

Demanding, skeptical and unsentimental. No reflexive praise, agreement, reassurance or fabricated criticism. Challenge concrete claims and contradictions; request numbers, baselines, counterfactuals and decisions under constraints. Simulate role priorities: recruiter motivation/communication/fit; hiring manager operating depth/results/team work; executive business judgment/strategy/resource allocation. Toughness targets answers, not personal identity; no insults or discriminatory questions. Never pretend to be the actual named interviewer.

Separate interviewer model from judge. **Jev is a decision model** using the existing typed OpenRouter Decisions API (`typesafe/jev-1.13`), not chat completions. Grade five dimensions: relevance, evidence, structure, credibility and depth. Use explicit anchored bands (0/25/50/75/100), strict evidence requirements and calibrated uncertainty. Derive overall score deterministically from valid dimensions; retain returned model/rubric version, confidence and evidence. Missing provider judgments are never zero or passing scores. Actionable prose may be generated by the interview LLM grounded in Jev's decisions and the transcript; label provenance. Final report must describe coverage and distinguish short/incomplete practices from full-duration sessions.

## Architecture and boundaries

Reuse Next.js dashboard and same-origin gateway, Python loopback service and canonical candidate/pipeline evidence. Separate interview SQLite storage from application state. LiveKit supplies room/WebRTC transport and Python agent runtime; ElevenLabs supplies streaming STT/TTS using the funded key in ignored `env.local` (`ELEVEN_LABS_API_KEY`, normalized server-side). OpenRouter supplies interviewer LLM and Jev scoring. Keys never enter browser props, tokens, logs or committed files. Browser receives a short-lived room-scoped participant token only.

No LiveKit credentials exist in env.local at initial inspection. The installed `lk` CLI is 2.15.0. Prefer local self-hosted LiveKit for MVP if cloud credentials are absent; document a cloud-ready env configuration. Do not silently substitute browser speech synthesis for ElevenLabs. Validate provider account access with bounded smoke calls and preserve unrelated active processes.

Context documents retain source identity and chunks. Retrieval must cover job, candidate and relevant previous-round material within a bounded token budget; use existing RAG where useful without coupling practice availability to an unrelated migration. Persist retrieval evidence per turn. Uploaded/source text is untrusted data, never instructions. Restrict job fetching to validated public URLs or supported ATS APIs; avoid arbitrary server-side URL fetching. Existing loopback Host/Origin protections apply to every interview route.

## API contract v1

All browser requests use `/api/imx` to Python paths below. JSON camelCase. IDs opaque; source secrets and filesystem paths excluded.

- `GET /interviews`: `{readiness, sessions}`; readiness describes configured versus tested/connected state.
- `POST /interviews`: `{company,title,jobUrl,jobDescription,round,persona,durationMinutes,resumeText,linkedinText,notes,targetScore,previousSessionId?}` -> full session.
- `GET /interviews/{id}` -> full session including status, created/started/ended/deadline timestamps, currentQuestion, documents, turns, report, contextWarnings.
- `POST /interviews/{id}/documents`: JSON `{kind,name,text}` or bounded raw binary with filename/kind headers -> session. Gateway translates UI file upload. Kinds include resume, notes, linkedin, prior_transcript, prior_recording.
- `POST /interviews/{id}/start`: `{}` -> session; establishes server deadline exactly once.
- `POST /interviews/{id}/connect`: `{}` -> `{url,token,roomName}`; room metadata contains session identifier only.
- `POST /interviews/{id}/turns`: `{answer,requestId,question?}` -> session; idempotent request ID; failed grading retryable without duplicate answer.
- `POST /interviews/{id}/finish`: `{}` -> session with final report; idempotent.

Provider seam: `readiness()`, `transcribe(bytes, filename)`, `score(context, question, answer)`, `question(context, turns)`, `connect(session)`. Voice runtime persists actual heard/spoken turns through shared API/store routines and isolates grading work from audio generation. Provider errors carry safe actionable messages, not raw credentials or entire upstream responses.
