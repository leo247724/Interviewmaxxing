## Decisions worth knowing

- **Grouping and openness are `holds`'s.** The sheet reuses `recorded_holds` and
  `hold_key`, so a hold answered since its stop (by `answer`, an earlier sheet or a saved
  answer for its wording) is neither listed nor touched. That is what makes a second
  `answer --sheet` a no-op and a regenerated sheet shorter.
- **Every application gets its own user input.** `answer --sheet` applies an entry to each
  application in `fields` through `user_input_for` and `save_user_inputs`, then saves the
  answer for reuse with the entry's scope (one global answer per wording; one job answer
  per application's job). The saved answers list is read once per run, so the second
  application of a global entry is still applied explicitly rather than counted as
  answered by the first.
- **Validation is per application, against the question as recorded there.** An answer
  that fits one employer's options and not another's is applied where it fits and reported
  by wording (`invalid`, N application(s)) where it does not. The sheet records the first
  application's options and, when others differ, `options_by_application`.
- **A required checkbox is only accepted checked**, as with `answer` (the core
  `answer_problems` rule); documented.
- **Proposals** come from the latest projected `routing.trace` of each stage for the
  field, stages in the order `question_equivalence` (the saved answer's value, from the
  profile by id), `status_derivation`, `option_equivalence`, `fact_screener` (kind choice
  only: a number or select-all trace names facts whose values are not recorded),
  `experience_screener` (YES/NO onto the yes/no option). A trace that passed its gate
  proposes nothing. `proposal_basis.confirmed` is always `false`; `apply_sheet` reads only
  `answer`.
- **The retry line** names `--batch-id` when given, else the batch whose ledger was written
  last; when that is a retry batch, the batch it retried (its ledger lists every
  application of the run, a retry's only those it selected). Documented.
- **`holds --sheet` refuses to overwrite** an existing sheet without `--force`, because a
  sheet may hold answers typed since. Not in the brief; added as the safe default.
- **Privacy.** The sheet is written with `os.open(..., 0o600)` and `chmod`ed. `holds
  --sheet` prints counts and the next command only; `answer --sheet` prints counts and
  wordings; validation messages from pydantic name the entry and field, never the value
  (`AnswerError` text, which quotes the value, is mapped to the kind `invalid`).

The container's pre-installed Chromium is Playwright revision 1194 while the locked
Playwright expects 1234 with a different directory layout, so the browser tests and the
e2e suite first failed with "Executable doesn't exist". They pass after symlinking the
expected `chromium-1234` and `chromium_headless_shell-1234` paths onto the installed
build under `/opt/pw-browsers` (outside the repository; nothing in the repository
changed for it). The first unit run, made before that bridge, had 40 browser-test
failures for that reason only; the full gate was rerun afterwards with the result above.
