### Start Date and End Date (`app_340209e9…`: NO_ANSWER)

Live holds:
- start: "Semantic decision is ambiguous";
- end: "No verified fact or saved answer answers this question".

Fix:
- `interviewmaxxing_generation.work_history` (new) reads the entry and part from the field
  path or section (`txt-workHistory-startDate-0`, `workHistory.currentlyWorkingHere.0`).
- The value comes from the profile's roles (`CandidateProfile.experience`). Entry 0 is the
  most recent role (a current one first, then by start).
- A date is written only in a format the question states (`MM/YYYY`, `YYYY-MM`, a month
  input).
- Every answer cites the role's verified facts; a role without any is not used.
- For a current role, the box is checked and the end date left blank: a non-blocking
  missing input that routing leaves alone.
- "I currently work here" is `CUSTOM_BOOLEAN`, not an attestation (`semantics.py`).

The live route decisions would still have held these answers:
- Jev reads the entry as the applicant's past (`HISTORICAL_OR_CONTEXTUAL`): 1.0 for the
  dates; 0.84 with 0.14 current, at confidence 0.80, for the box.
- For that scope the profile copy is never allowed.

So `routing._gate` now admits exactly this derivation (`_own_work_history`, traced
`work_history`): the same value and the same role's facts, a sure `COPY_KNOWN` route, and
the applicant's own source, current plus historical at 0.95 or more. Another person's
dates never pass.

Mock `paylocity-work-history`: the end date is disabled and hidden while the box is checked.

## 5. CAPTCHAs through 2Captcha

Done in a fork on `build/wp1-round14-captcha` (`a5a605a`), merged here as `60fdf9f`.
Details are in `docs/dynamic-runtime.md` ("Round 14: CAPTCHA solving (2Captcha)") and
`docs/mass-preparation.md` ("CAPTCHAs").

**How it is switched on.**
- Off by default: `--captcha-solver 2captcha` (or `IMX_CAPTCHA_SOLVER=2captcha`), within
  `--captcha-budget-usd` (default 2.00).
- On `apply`, `resume`, `prepare-batch`, `submit` and `submit-approved`; a retry inherits
  them.
- The key is `TWOCAPTCHA_API_KEY`, read through the existing env-file loader (the file the
  OpenRouter key comes from, else the process environment). It goes only into 2Captcha
  request bodies and is never printed or logged.
- Without a key the solver is simply off.

**Solving.**
- `captcha.py` detects reCAPTCHA v2 (checkbox, invisible, Enterprise), reCAPTCHA v3,
  hCaptcha and Turnstile with a fixed read-only script: site key, invisible, answered,
  submit-bound, callback.
- It asks the 2Captcha API v2 (`createTask`, then `getTaskResult`): first poll after 10 s,
  then every 5 s, at most 120 s.

**Where the token goes** (Playwright only; nothing is clicked):
- a CAPTCHA page in front of the form: the token and the widget's callback, then the page
  it leads to;
- a widget on a step before the last: the token only, before `advance`;
- a widget on the final step: never in preparation; only the approved `submit` answers it,
  right before its gated submit.

**Solving never submits anything.** A callback is called only on a CAPTCHA page that has
nothing to fill.

**Never solved, and nothing spent:**
- an invisible reCAPTCHA bound to the submit button;
- a CAPTCHA page that also holds a form;
- OpenCLI sessions, which only run read-only scripts.

**Spend cap and records.**
- Each solve reserves USD 0.003, then is settled at the reported cost.
- A batch's jobs share `<batch dir>/captcha-spend.jsonl`, so the cap holds per batch.
- Each attempt is a `captcha.solve` event: kind, outcome, seconds, cost, error code and
  site host; never the token.
- An attempt that reached 2Captcha is also a `provider.budget` event (purpose `captcha`),
  so batch and dashboard costs include it.

**Fallback.** When the solver is off or has no key, the budget is spent, 2Captcha
errors, 120 s pass, the page refuses the token, the case is unsupported, or a run passes
3 attempts, the run stops as before: NEEDS_INPUT "Solve the CAPTCHA".

**Tests.** `tests/browser/test_captcha_round14.py` (30) and
`tests/core/test_captcha_round14_cli.py` (18) use a fake 2Captcha transport and the mock
jobs `captcha-gate`, `captcha-form` and `captcha-steps`. No real 2Captcha call was made.

**Open (from the fork):**
- Nothing is verified on a live site.
- Service (dashboard) runs do not get the solver.
- A token the site refuses is still charged: incorrect solves are not reported to 2Captcha.
- `submit-approved --batch B` spends from B's preparation ledger.
- With the solver on, each non-final step gets one extra page read before Next.
- A refused solve waits about 20 s before falling back.
